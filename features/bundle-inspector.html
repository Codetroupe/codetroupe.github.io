Pro Feature

Bundle Inspector

Deep analysis of your Android App Bundles. Track size across versions, audit resources for redundancy, and understand exactly what ships to your users.

Overview

Bundle Inspector opens up any .aab file and gives you a complete view of its contents — modules, resource configurations, native libraries, and asset files. It goes beyond simple file listing by providing version-to-version size diffs, resource redundancy scanning, WebP conversion suggestions, and Git commit association so you can trace size regressions to specific changes. All build size history is stored locally on your machine.

Key Capabilities

AAB File Analysis

Open any AAB file and inspect its internal structure. Bundle Inspector shows all included modules (base, dynamic features, asset packs), their individual sizes, and the configuration splits (ABI, screen density, language) that Google Play will use to generate device-specific APKs. Drill down into each module to see its file tree with sizes for every entry.

Size Tracking with Version Diffs

Every inspected bundle is recorded with its total size, module breakdown, and version code. Compare any two versions side-by-side to see exactly what grew or shrank. The diff view highlights which modules, resources, or native libraries contributed to size changes, making it easy to catch unexpected bloat before release.

Resource Redundancy Scanning

Bundle Inspector scans your bundle for duplicate or near-duplicate resources — identical images in different drawable folders, unused string translations, or redundant layout files. Redundant resources are grouped by type and sorted by potential size savings so you can prioritize what to clean up first.

WebP Conversion Suggestions

PNG and JPEG images that would benefit from WebP conversion are flagged with estimated size savings. Bundle Inspector calculates the difference between the current format and a WebP equivalent at comparable quality, giving you a clear picture of how much space you can reclaim. Suggestions include the file path and estimated savings in kilobytes.

Git Commit Association

When your project is under Git version control, Bundle Inspector associates each build with the current commit hash. The size history view shows commit messages alongside size data, so you can answer questions like "which commit caused the 2 MB jump in native libraries?" without manually cross-referencing logs.

Build Size History

All inspected builds are stored locally in a lightweight database. The history view shows a chronological list with version code, total size, and module breakdown. Trend indicators highlight builds where the size changed significantly compared to the previous entry, helping you spot regressions at a glance.

Usage

Bundle Inspector is accessible from Tools > ADB Pro > Inspect Bundle... or from the ADB Pro side panel. To use it:

  • Select an .aab file from your build output or browse to any bundle on disk
  • The analysis panel opens automatically with the full module and resource breakdown
  • Click "Compare with..." to diff against a previously inspected version
  • Click "Run Audit" to scan for redundancy, WebP opportunities, and oversized assets
  • Size history is viewable from the "History" tab in the inspector panel

Settings

Bundle Inspector settings are accessible from Settings > Tools > ADB Pro > Bundle Inspector. You can configure:

  • Size history retention period (default: keep all entries)
  • WebP quality threshold for conversion suggestions (default: 80%)
  • Minimum file size for oversized asset warnings (default: 500 KB)
  • Git integration toggle (auto-detect commit hash)
