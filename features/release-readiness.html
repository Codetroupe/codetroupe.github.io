Pro Feature

Release Readiness

A comprehensive 13-point pre-release checklist that catches misconfigurations, security issues, and policy violations before your app reaches the Play Store.

Overview

Releasing an Android app involves more than just building a release APK. Release Readiness automates the pre-flight checks that experienced developers run through manually — and that inexperienced developers often skip entirely. Each of the 13 checklist items inspects your project configuration, manifest, build outputs, and dependencies to produce a clear pass/fail result with actionable details. Run it before every release to catch issues early and build confidence in your shipping build.

Key Capabilities

Debuggable Flag Check

Verifies that the android:debuggable attribute is set to false in the release build. A debuggable release build exposes your app to security risks and is automatically rejected by the Play Store. This check also scans for BuildConfig.DEBUG usage that may inadvertently enable debug behavior in production.

MinifyEnabled Verification

Confirms that code shrinking (R8/ProGuard) is enabled for the release build type via minifyEnabled true. Unminified release builds are larger, slower to install, and expose your source code to reverse engineering. The check includes resource shrinking (shrinkResources true) status as well.

API Key Exposure Scan

Scans your source code and resource files for hardcoded API keys, secrets, and tokens using pattern matching. Detects common patterns for Google Maps keys, Firebase config values, AWS credentials, and third-party SDK tokens. Hardcoded secrets in release builds are a critical security vulnerability.

SDK Version Compliance

Validates that your targetSdkVersion meets the current Google Play requirements. Google periodically raises the minimum target SDK for new app submissions and updates. This check also verifies that compileSdkVersion is sufficient for the libraries in use and flags any deprecated API usage.

Signing Configuration

Ensures the release build is signed with a proper release keystore — not the debug keystore. Checks that the signing config uses v2 or v3 APK Signature Scheme (required for Play App Signing) and that the keystore certificate validity period extends beyond the app's expected lifespan.

ProGuard Rules Review

Verifies that ProGuard/R8 rules files exist and are properly referenced in the build configuration. Flags common issues like missing -keep rules for reflection-heavy libraries, overly broad wildcard rules, and rules that may strip required code paths.

Version Code and Name

Checks that versionCode is incremented compared to the last known release and that versionName follows semantic versioning conventions. A stale version code will cause Play Store upload failures, and inconsistent version names confuse users and QA teams.

Target SDK Version

Goes beyond basic SDK compliance by checking runtime permission behavior changes, background execution limits, and other platform-level requirements introduced in recent Android versions. Ensures your app handles the behavioral changes required by its target API level.

Permissions Review

Lists all permissions declared in the manifest and highlights potentially sensitive ones (location, camera, microphone, contacts, phone state). Flags permissions that lack corresponding runtime permission request code, which would cause crashes on Android 6.0+. Also detects unused permissions that should be removed to reduce the app's attack surface.

Test Coverage

Checks for the presence of test source sets and optionally runs unit tests to verify they pass before release. While ADB Pro does not enforce a specific coverage threshold, it reports whether tests exist, whether they pass, and the last execution timestamp.

Resource Optimization

Verifies that resource shrinking is enabled, checks for unused resources detected by Android Lint, and flags large image assets that could benefit from WebP conversion or vector drawable replacement. Unoptimized resources bloat your APK and increase install abandonment.

Manifest Checks

Validates critical manifest attributes: android:allowBackup (should be false or configured with rules), android:usesCleartextTraffic (should be false in production), android:exported on all components (required on Android 12+), and android:networkSecurityConfig presence.

Dependency Audit

Scans your dependency tree for known vulnerabilities using public CVE databases. Flags outdated dependencies with available security patches, snapshot versions that should not appear in release builds, and conflicting transitive dependencies that may cause runtime issues.

Usage

Release Readiness can be triggered from multiple entry points:

  • Tools > ADB Pro > Run Release Readiness Check — runs the full 13-point checklist
  • ADB Pro side panel — click the "Release Readiness" tab and press "Run Check"
  • Post-build hook — optionally configure the check to run automatically after every release build

Each failed item includes a description of the issue, the affected file or configuration, and a suggested fix. Click on any failed item to navigate directly to the source location in your editor.

Settings

Release Readiness settings are accessible from Settings > Tools > ADB Pro > Release Readiness. You can configure:

  • Enable or disable individual checklist items (e.g., skip test coverage for internal builds)
  • Custom API key patterns for the exposure scan
  • Minimum required targetSdkVersion (overrides automatic detection)
  • Auto-run on release build completion
  • Severity threshold for blocking release (require all pass, or allow warnings)
