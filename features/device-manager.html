Core Module

Device Manager

Automatic ADB device discovery with connection monitoring, TTL caching, emulator detection, and seamless device selection for install operations.

Overview

Device Manager is the foundation that other ADB Pro modules build on. It handles the critical task of finding and managing connected Android devices — both physical hardware and emulators. Instead of manually configuring ADB paths or running adb devices in a terminal, Device Manager automatically discovers the ADB binary, polls for connected devices with intelligent TTL caching, and provides a clean device list that other modules (AAB Tools, Build Tools, Signing Tools) consume when they need to install an APK or target a specific device.

Key Capabilities

Automatic ADB Path Discovery

Device Manager locates the ADB binary without manual configuration. It checks multiple sources in order: the ANDROID_HOME and ANDROID_SDK_ROOT environment variables, the Android SDK path configured in your IDE (Settings > Languages & Frameworks > Android SDK), common SDK installation paths (e.g., ~/Library/Android/sdk on macOS, %LOCALAPPDATA%\Android\Sdk on Windows), and the system PATH. The first valid ADB binary found is used automatically. If multiple ADB versions are detected, the most recent one is preferred.

Device Listing with Connection Status

The device list shows every connected device with its serial number, model name, Android version, API level, and connection state (device, unauthorized, offline, no permissions). Devices in the unauthorized state are flagged with a prompt to accept the USB debugging authorization on the device itself. Offline and disconnected devices are grayed out but remain visible so you can track when they come back online.

TTL Caching (5-Second Default)

Polling adb devices on every UI interaction would be wasteful and slow. Device Manager caches the device list with a configurable time-to-live (TTL), defaulting to 5 seconds. Within the TTL window, device queries return instantly from cache. Once the TTL expires, the next query triggers a background refresh. This approach keeps the UI responsive while ensuring the device list is never more than a few seconds stale. The TTL is adjustable from 1 to 30 seconds in settings.

Device Selection for Install Operations

When AAB Tools or Build Tools need to install an APK, they query Device Manager for the target device. If a single device is connected, it is selected automatically. If multiple devices are connected, Device Manager presents a chooser dialog with device details so you can pick the right target. The last-selected device is remembered for the session, so repeated installs go to the same device without prompting.

Emulator Detection

Device Manager distinguishes between physical devices and emulators by parsing the device serial number format (emulator-5554 for emulators, USB serial numbers for physical devices). Emulators are displayed with a distinct icon and show additional details like the AVD name and snapshot status. This distinction matters for install operations — some teams prefer to test on emulators during development and only deploy to physical devices for release testing.

Connection Monitoring

Device Manager runs a background listener that detects when devices are connected or disconnected. When a new device appears, the device list refreshes automatically and a notification appears in the IDE status bar. When a device disconnects mid-operation (e.g., during an APK install), the operation is paused gracefully and resumes when the device reconnects or a new device is selected. This prevents cryptic ADB error messages from surfacing to the user.

ADB path resolution order

1. $ANDROID_HOME/platform-tools/adb
2. $ANDROID_SDK_ROOT/platform-tools/adb
3. IDE Android SDK path (Settings > Android SDK)
4. ~/Library/Android/sdk/platform-tools/adb    (macOS)
5. %LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe (Windows)
6. ~/Android/Sdk/platform-tools/adb            (Linux)
7. System PATH (which adb / where adb)

# First valid binary found is used.

Usage

Device Manager operates automatically in the background, but you can interact with it directly:

  • ADB Pro side panel — the "Devices" tab shows the current device list with status indicators
  • Tools > ADB Pro > Refresh Devices — force an immediate device list refresh, bypassing the TTL cache
  • Tools > ADB Pro > Select Device... — open the device chooser dialog manually
  • Device context actions — right-click a device for actions like "Open Shell", "Reboot", or "Disconnect"

Settings

Device Manager settings are accessible from Settings > Tools > ADB Pro > Device Manager. You can configure:

  • Custom ADB binary path (override automatic discovery)
  • Device list TTL in seconds (default: 5, range: 1-30)
  • Connection monitoring toggle (background listener for device events)
  • Default device preference (prefer physical devices over emulators, or vice versa)
  • Auto-select when only one device is connected (enabled by default)
  • Status bar device indicator (show current device in the IDE status bar)
