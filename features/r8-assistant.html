R8 Assistant

Intelligent code obfuscation made easy. Auto-detect your dependencies, generate correct keep rules, and harden your app with custom obfuscation dictionaries.

Introduction

The R8 Assistant takes the guesswork out of ProGuard/R8 configuration. It scans your project's dependencies, identifies libraries that need special keep rules, and generates an optimized proguard-rules.pro file tailored to your stack.

Beyond rule generation, it provides a comprehensive suite of obfuscation tools: a reflection risk scanner that catches code patterns that silently break after obfuscation, mapping file analysis for understanding build outputs, stack trace deobfuscation for production crash reports, and a library of 11 preset obfuscation dictionaries that use Unicode confusable characters for maximum code protection.

The R8 Assistant is accessible from the R8 Assistant tab in the ADB Pro tool window, giving you a single panel to manage every aspect of code shrinking and obfuscation.

Why Use R8 Assistant?

ProGuard and R8 configuration is one of the most error-prone parts of Android release builds. Here are the problems developers face without proper tooling:

  • A single missing -keep rule crashes your app in production — but only after release. R8 strips and renames aggressively, and the resulting ClassNotFoundException or NoSuchMethodError won't appear during debug builds.
  • There are 20+ popular libraries, each needing specific rules. Retrofit, Gson, Moshi, Room, Hilt, Kotlin Coroutines, and many more all require unique ProGuard configurations. Tracking them manually across library upgrades is unsustainable.
  • Reflection-based code silently breaks after obfuscation. Calls to Class.forName(), getMethod(), or JSON serialization via field-name matching work fine in debug but fail when class and field names are obfuscated.
  • No tool tells you which rules you're missing. The compiler won't warn you, your tests pass in debug, and the crash only surfaces on real devices running release builds — the worst possible feedback loop.

Features

Rule Recommendation

Scans your build.gradle dependencies and recommends ProGuard/R8 rules from a database of 20+ popular libraries including Retrofit, Gson, Moshi, Room, Hilt, Kotlin Coroutines, and more. Each recommendation includes comments explaining why the rule is needed.

Generated proguard-rules.pro
# ── ADB Pro R8 Assistant ── Generated Rules ──────────
# Detected: Retrofit 2.9.0, Gson 2.10.1, Room 2.6.0

# Retrofit
-keepattributes Signature, *Annotation*
-keep class retrofit2.** { *; }
-keepclasseswithmembers class * {
    @retrofit2.http.* <methods>;
}

# Gson
-keep class com.google.gson.** { *; }
-keepclassmembers class * {
    @com.google.gson.annotations.SerializedName <fields>;
}

# Obfuscation Dictionary
-obfuscationdictionary proguard-dic-encoding-chaos.txt

Reflection Risk Scanner

Scans your source code for reflection-based patterns that can break after obfuscation. Detects usages of Class.forName(), getMethod(), getDeclaredField(), and JSON serialization libraries that rely on field name matching. The scanner produces a categorized report:

Risk Level Pattern Action Needed
High Class.forName("com.example.MyClass") Add -keep rule for target class
High getDeclaredMethod("processData") Add -keepclassmembers for method
Medium Gson fromJson() on data class Add -keepclassmembers for fields
Low getResourceAsStream() Verify resource path after obfuscation

Mapping File Analysis

Load and analyze mapping.txt files from R8/ProGuard builds. View class and method renaming statistics, identify heavily obfuscated packages, and search for specific class mappings to understand exactly how your code was transformed.

Stack Trace Deobfuscation

Paste a stack trace from a production crash and deobfuscate it using your mapping file. Supports both R8 and ProGuard mapping formats. Integrates with remote mapping file storage so you can resolve crash reports against the exact mapping used for that release.

Rule Tester

Validate your ProGuard rules before running a full release build. The rule tester checks for common syntax errors, conflicting rules, and overly broad keep patterns that could inflate your APK size. Catch misconfigurations in seconds instead of waiting for a multi-minute build.

Obfuscation Dictionaries

Download and apply preset obfuscation dictionaries that use Unicode confusable characters for maximum code protection. 11 preset dictionaries are available — from visual lookalikes (Greek, Cyrillic) to cross-encoding confusion (characters that display differently in GBK, Big5, Shift-JIS).

Getting Started

Follow these steps to generate and apply ProGuard/R8 rules for your project:

  1. Open the R8 Assistant tab in the ADB Pro tool window.
  2. Click "Generate Rules" — the assistant scans your build.gradle dependencies and produces recommended keep rules.
  3. Review the generated rules in the panel. Each rule includes a comment explaining which library it targets and why it is needed.
  4. Copy the generated rules into your proguard-rules.pro file (or use the one-click apply button).
  5. Run the Reflection Risk Scanner to check for code patterns that may break after obfuscation.
  6. Build a release APK with minifyEnabled true to verify everything works.

Additional configuration is available at Settings > Tools > ADB Pro > R8 Assistant, where you can customize:

  • Custom proguard-rules.pro file path (override auto-detected location)
  • Preferred dictionary download URL (defaults to the built-in GitHub Pages CDN)
  • Reflection scan scope (source directories to include/exclude)
  • Mapping file auto-detection paths

Verification

After applying generated rules and building a release APK, confirm that the R8 Assistant is working correctly:

  • Run a release build with minifyEnabled true and shrinkResources true — the build should complete without errors.
  • Launch the release APK on a device or emulator and verify that the app does not crash on startup or during normal use.
  • Use jadx or the Android Studio APK Analyzer to inspect the APK and confirm that class names are obfuscated (renamed to short or dictionary-based names).
  • Check that mapping.txt was generated in app/build/outputs/mapping/ — this file is essential for deobfuscating crash reports.
  • Run the Reflection Risk Scanner and confirm that all high-risk items have corresponding -keep rules in your ProGuard configuration.
