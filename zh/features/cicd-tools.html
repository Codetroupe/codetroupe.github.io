CI/CD Tools

根据 Android 项目配置生成 GitHub Actions、GitLab CI 或 Jenkins 发布流水线。

介绍

CI/CD Tools 将本地 IDE 中验证过的 Android 构建流程转成可提交到仓库的流水线配置。

为什么使用 CI/CD Tools

Android CI/CD 需要正确处理 JDK、Gradle cache、签名密钥、构建任务、产物上传、mapping 保存和发布检查。手写脚本容易遗漏细节。

核心能力

  • 扫描项目模块、Gradle wrapper、构建任务和签名需求。
  • 生成 GitHub Actions、GitLab CI 或 Jenkins 配置。
  • 拆清 secret、keystore、产物路径和 release 检查步骤。
  • 让本地 IDE 构建流程和 CI 构建流程保持一致。

功能细节

能力 1

扫描项目模块、Gradle wrapper、构建任务和签名需求。

能力 2

生成 GitHub Actions、GitLab CI 或 Jenkins 配置。

能力 3

拆清 secret、keystore、产物路径和 release 检查步骤。

能力 4

让本地 IDE 构建流程和 CI 构建流程保持一致。

典型工作流

  1. 选择目标 CI 平台和构建任务。
  2. 配置 JDK、Gradle cache、签名 secret 和产物上传规则。
  3. 预览生成的 YAML 或 pipeline 配置。
  4. 提交到仓库并在 CI 中验证构建结果。

适合的使用场景

  • 为 Android 项目快速建立可复用的 CI 构建。
  • 把 APK/AAB、mapping、测试报告作为 CI artifact 保存。
  • 统一团队本地发布和自动化发布步骤。

开始使用

  1. 在 ADB Pro 工具窗口中打开 CI/CD Tools 标签页。
  2. 确认当前 Android 项目已经完成 Gradle 同步，并选择需要处理的模块或产物。
  3. 按页面提示执行扫描、分析或生成操作。
  4. 查看结果、日志和建议，再决定是否应用到项目配置中。

验证方式

  • 重新执行相关 Gradle 构建或分析任务，确认没有新的错误。
  • 检查输出日志和 IDE 面板结果，确认状态、路径和产物符合预期。
  • 如果改动会影响 release 包，建议结合 Release Readiness 再做一次发布前检查。

常见问题

这个功能会直接修改项目文件吗？

默认以扫描、分析和结果展示为主。只有在你明确执行应用、生成或注入配置等操作时，才会修改项目文件。

适合在发版前什么时候运行？

建议在 release 构建产物生成后运行，并在上传应用商店或交给 QA 前结合 Release Readiness 做一次完整确认。

它和其他 ADB Pro 功能如何配合？

这个功能通常和 Build Tools、AAB Tools、Signing Tools 或 Release Readiness 串联使用，用来把单点操作放进完整 Android 发版流程。
