核心模块

AAB Tools

在 IDE 内完成 AAB 查找、APKS 转换、签名配置、设备选择和安装，减少 bundletool、ADB、文件管理器之间的来回切换。

解决什么问题

AAB 是发布格式，不是可以直接安装到 Android 设备上的 APK。通常你需要使用 bundletool 生成 APKS，再根据设备配置安装对应的 APK split。ADB Pro 把这条链路放进一个可视化面板中。

当项目有多个构建产物或远程 CI 发布包时，AAB Tools 可以扫描本地 Gradle 输出目录，也可以扫描 GitHub / GitLab release assets，帮助 QA 或发版负责人快速拿到候选包。

单设备 Split 与多设备 Universal

如果你只测试一台目标设备，可以使用设备相关的 Split APKS，这更接近 Google Play 根据设备分发的结果。插件可以从目标设备读取 ABI、density、locale 等配置。

如果你要把同一个 AAB 安装到多台已连接设备，批量安装会使用 Universal APK 模式，避免某台设备生成的 split APK 在另一台设备上因为 ABI、屏幕密度或语言不匹配而安装失败。

核心能力

  • 自动发现本地 AAB 构建产物，并显示大小、变体和修改时间。
  • 读取 Gradle signingConfigs，减少手动填写 keystore 信息。
  • 管理 bundletool.jar，避免每个项目重复配置命令行路径。
  • 支持远程 AAB 扫描，适合测试 CI 生成的 release candidate。
  • 支持选择多个在线设备执行 Universal APK 批量安装，并显示每台设备的安装结果。

适合的使用场景

日常开发中，它适合快速验证 AAB 能否被正确转换和安装；发版前，它适合把候选包分发到多台测试设备做 smoke test；而需要完整发版治理时，可以继续配合 Release Readiness、Signing Tools、Bundle Inspector 和 Res Guard 使用。
