核心模块

AAB Tools

IDE 内完整的 Android App Bundle 工具集。转换、签名、安装到单个设备、批量安装到选中设备、管理 bundle，全部在一个面板中完成。

介绍

AAB Tools 是 ADB Pro 的核心模块，为 Android App Bundle（.aab）提供转换、签名和安装工作流。它把 Google bundletool 包装成可视化 UI，并自动处理二进制工具管理、设备检测和签名配置。

当你构建 release 应用时，Gradle 通常生成的是 .aab，而不是可以直接安装的 APK。要在真机或模拟器测试这个 bundle，需要把它转换为 .apks，使用有效 keystore 签名，再通过 ADB 推送。AAB Tools 将这些步骤合并到一个面板中。

对于设备实验室场景，AAB Tools 也可以把同一个 AAB 顺序安装到多个在线设备。批量安装使用 Universal APK 模式，避免为某一台设备生成的 split APK 在另一台设备上因为 ABI、density 或 locale 不匹配而失败。

对于 QA 和发布负责人，AAB Tools 还支持扫描 GitHub、GitLab 等远程仓库中的 release candidate bundle，形成下载、转换、安装的 IDE 内闭环。

为什么使用 AAB Tools？

手动处理 Android App Bundle 时，每一步都会增加发布链路摩擦：

  • bundletool 命令复杂。 需要单独下载 bundletool，记住 build-apks、--mode=universal、--connected-device 等参数，并手动指定输出路径。
  • keystore 管理有额外成本。 每次转换都要指定 keystore、alias 和密码。debug/release keystore 切换时，容易出现路径或凭据错误。
  • 缺少远程仓库支持。 从 GitHub 或 GitLab 测试 release candidate 时，通常要先手动下载 AAB，再重复本地转换和安装。
  • 工具链割裂。 标准流程会在 Gradle 输出、bundletool CLI、adb install 和文件管理器之间跳转。
  • 容易拿错构建产物。 多模块、多 flavor 项目中，正确的 .aab 可能散落在多个输出目录。

功能

AAB 转 APKS

ADB Pro 自动发现 Gradle 构建产出的 .aab 文件，并使用 bundletool 转换为 .apks。bundletool 会由插件自动下载、检查版本和管理，不需要手动安装。

一键安装

AAB 转换为 APKS 后，ADB Pro 可以一键安装到任意连接设备或模拟器。插件负责 ADB 路径发现、设备枚举和安装状态回写。

Universal APK 批量安装

当一个 AAB 要安装到多台设备时，ADB Pro 会为批量操作使用 Universal APK 转换。这可以避免 split APK 与另一台设备 ABI、屏幕密度或语言环境不匹配导致的失败。

签名配置

AAB Tools 可以从 build.gradle 或 build.gradle.kts 中解析 signingConfigs，并自动填充 keystore 路径和 alias。密码通过 IntelliJ PasswordSafe 保存，不会写入明文配置文件或 shell 历史。

远程仓库扫描

可以配置 GitHub 或 GitLab 仓库，扫描 release assets 中的 AAB 文件。面板会展示版本 tag、下载大小和上传时间，适合 QA 测试 CI 产出的候选包。

文件扫描

自动扫描项目的 build/outputs/bundle/ 等常见目录，最新构建产物会按修改时间出现在面板中。

AAB 文件选择对话框

当存在多个 AAB 文件时，可以按文件名、大小、修改时间和变体信息选择具体要转换或安装的 bundle，也支持选择项目外部下载的 AAB。

远程 AAB 缓存

从远程仓库下载的 AAB 会被本地缓存，避免每次安装都重新下载。缓存会根据时间和磁盘空间自动管理。

转换模式选项

支持 universal APK、设备专属 split APK 和 standalone APK。也可以按 ABI、屏幕密度或 locale 过滤 split，生成更适合目标设备的输出。

Gradle 签名配置集成

插件可以直接读取 build.gradle.kts 中的签名配置，确保 APKS 使用和生产构建一致的签名凭据，避免安装时出现签名不匹配。

开始使用

AAB Tools 设置位于 Settings > Tools > ADB Pro > AAB Tools，可以配置：

  • 自定义 bundletool 路径，覆盖插件自动管理版本。
  • 默认签名配置和常用 keystore。
  • 远程仓库凭据和扫描规则。

快捷操作也可以从 Tools > ADB Pro 菜单进入：Quick Install AAB、Select and Install AAB、Convert AAB to APKS 和 Install APKS File。

典型 AAB Tools 工作流
# 1. 构建 app bundle
./gradlew bundleRelease

# 2. ADB Pro 自动检测 .aab 输出
# 3. 在 AAB Tools 面板点击 Convert
# 4. 选择单个目标设备，或选择多个批量设备
# 5. 单设备安装使用 split APKS，批量安装使用 Universal APK

验证

  • 转换后确认 .apks 文件出现在输出目录中。
  • 安装后确认目标设备或模拟器能启动应用，并显示预期 versionName 和 versionCode。
  • 批量安装时检查每个选中设备行，确认单设备安装结果成功。
  • 使用 apksigner verify --verbose --print-certs app.apks 确认签名证书匹配所选 keystore。
  • 使用 adb shell pm list packages | grep <your.package> 确认设备已安装正确包名。
  • 远程仓库下载场景下，确认 AAB SHA-256 与 release notes 中记录一致。
