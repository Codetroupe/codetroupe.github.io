发版检查

Release Readiness

在 APK 或 AAB 上传前自动检查常见发版风险，把隐藏在配置、签名、SDK、混淆和原生库里的问题提前暴露出来。

为什么需要发版检查

很多 Android 发版问题不是编译错误，而是配置遗漏：debuggable 没关、release 签名不对、R8 没启用、API Key 被打进包里、targetSdk 不符合要求，或者远程构建包和本地预期不一致。

Release Readiness 把这些检查放在 IDE 内，帮助你在上传 Google Play 或其他应用商店前先做一次结构化确认。

覆盖的检查方向

  • Manifest 与构建类型：debuggable、cleartext traffic、release build 标识。
  • R8 / ProGuard：代码压缩、资源压缩、数据库实体或反射相关 keep 规则。
  • 签名身份：release keystore、证书指纹、上传签名配置。
  • 版本与商店规则：versionCode、versionName、targetSdk 合规性。
  • 安全风险：硬编码 API Key、测试域名、敏感配置。
  • 兼容性：Android 15+ 设备相关的 16 KB native library page-size 检查。

远程 AAB 和 versionCode

检查可以针对本地构建产物，也可以针对配置仓库中下载的远程 AAB。远程缓存只代表产物来源，不会被误判成 debug 或非 release 构建。

versionCode 检查会把本地历史当作提醒，而不是盲目阻断。真正需要确认的是目标应用商店已经接受或上传过的版本号基线。

文档依据

每个检查结果都可以提供 Docs 入口，方便你从具体告警跳转到对应说明或官方依据。这对团队 review 很有帮助，因为它把“为什么要修”讲清楚了。
