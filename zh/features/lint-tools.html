Lint Tools

在 IDE 内运行 Android Lint，查看严重级别、问题位置和 baseline 状态。

介绍

Lint Tools 将 Android Lint 报告解析成可浏览的 IDE 面板，让发布前的质量问题更容易被发现、过滤和处理。

为什么使用 Lint Tools

Lint 报告通常分散在 Gradle 输出、HTML 报告或 CI 日志里。开发者需要快速区分发布风险、历史遗留问题和当前改动引入的新问题。

核心能力

  • 运行项目或模块级 Android Lint。
  • 按严重级别、类别和文件位置展示问题。
  • 结合 baseline 判断哪些问题需要在当前版本处理。
  • 将发版相关风险纳入 Release Readiness 检查链路。

功能细节

能力 1

运行项目或模块级 Android Lint。

能力 2

按严重级别、类别和文件位置展示问题。

能力 3

结合 baseline 判断哪些问题需要在当前版本处理。

能力 4

将发版相关风险纳入 Release Readiness 检查链路。

典型工作流

  1. 选择项目或模块并运行 Lint 分析。
  2. 按 Fatal、Error、Warning 等级过滤结果。
  3. 查看问题说明、位置和可能修复方向。
  4. 更新 baseline 或修复关键发布问题。

适合的使用场景

  • 发布前过滤 Fatal、Error、Warning 级别问题。
  • 维护 lint baseline，避免旧问题淹没新问题。
  • 在 IDE 内快速定位 Android 配置、资源和兼容性告警。

开始使用

  1. 在 ADB Pro 工具窗口中打开 Lint Tools 标签页。
  2. 确认当前 Android 项目已经完成 Gradle 同步，并选择需要处理的模块或产物。
  3. 按页面提示执行扫描、分析或生成操作。
  4. 查看结果、日志和建议，再决定是否应用到项目配置中。

验证方式

  • 重新执行相关 Gradle 构建或分析任务，确认没有新的错误。
  • 检查输出日志和 IDE 面板结果，确认状态、路径和产物符合预期。
  • 如果改动会影响 release 包，建议结合 Release Readiness 再做一次发布前检查。

常见问题

这个功能会直接修改项目文件吗？

默认以扫描、分析和结果展示为主。只有在你明确执行应用、生成或注入配置等操作时，才会修改项目文件。

适合在发版前什么时候运行？

建议在 release 构建产物生成后运行，并在上传应用商店或交给 QA 前结合 Release Readiness 做一次完整确认。

它和其他 ADB Pro 功能如何配合？

这个功能通常和 Build Tools、AAB Tools、Signing Tools 或 Release Readiness 串联使用，用来把单点操作放进完整 Android 发版流程。
