Build Tools

在 JetBrains IDE 内执行 Gradle 构建、管理变体、批量生成 APK/AAB，并快速定位构建产物。

介绍

Build Tools 将常见 Gradle 构建入口、构建历史和产物定位集中到一个面板。它适合多 flavor、多 build type 和多模块 Android 项目，避免开发者在终端、文件管理器和 IDE 之间来回切换。

为什么使用 Build Tools

Android 项目经常存在多个 flavor、build type 和渠道包。只靠命令行构建时，开发者需要反复确认任务名、输出目录、版本信息和产物位置，容易在发版前拿错包或漏掉某个变体。

核心能力

  • 识别 Android 模块、构建变体和常见 Gradle 任务。
  • 从 IDE 面板执行 assemble、bundle 或自定义构建任务。
  • 记录构建状态、耗时、输出路径和最近构建历史。
  • 从构建结果直接打开 APK/AAB 所在目录，继续签名、检查或安装。

功能细节

典型工作流

  1. 扫描当前 Android 项目的 Gradle 模块、变体和常用构建任务。
  2. 选择 release/debug 或 flavor 组合并执行构建。
  3. 查看构建日志、耗时和输出产物路径。
  4. 将生成的 APK/AAB 交给 Signing Tools、AAB Tools 或 Release Readiness 继续处理。

适合的使用场景

  • 多 flavor、多渠道或多应用项目的日常构建。
  • 发版前生成 release APK/AAB 并记录候选产物。
  • 需要在 IDE 内完成构建、定位产物和后续发布检查的团队。

开始使用

  1. 打开 ADB Pro 的 Build Tools 标签页。
  2. 确认 Gradle 项目已经同步，并刷新模块和变体列表。
  3. 选择目标任务，例如 assembleRelease 或 bundleRelease。
  4. 构建完成后从结果列表打开产物目录或继续执行发布检查。

验证方式

  • 确认 Gradle 任务成功结束，日志中没有失败任务。
  • 确认 APK/AAB 输出路径、variant、versionName 和 versionCode 正确。
  • 将候选产物交给 Release Readiness 或 AAB Tools 做进一步验证。

常见问题

这个功能会直接修改项目文件吗？

默认以扫描、分析和结果展示为主。只有在你明确执行应用、生成或注入配置等操作时，才会修改项目文件。

适合在发版前什么时候运行？

建议在 release 构建产物生成后运行，并在上传应用商店或交给 QA 前结合 Release Readiness 做一次完整确认。

它和其他 ADB Pro 功能如何配合？

这个功能通常和 Build Tools、AAB Tools、Signing Tools 或 Release Readiness 串联使用，用来把单点操作放进完整 Android 发版流程。
