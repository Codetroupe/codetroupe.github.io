资源混淆

Android AAB 资源混淆指南：AabResGuard、白名单与 Gradle 插件 JAR

解释 AAB/APK 资源混淆、AabResGuard 白名单、项目内插件 JAR 管理，以及 ADB Pro 如何生成更安全的资源混淆配置。

约 10 分钟

快速结论：资源混淆会重命名 Android 资源标识，但必须通过白名单保护运行时依赖的资源，并保持 Gradle 插件配置可复现。

开发者常问的问题

  • Android AAB 如何做资源混淆？
  • Firebase 或广告 SDK 哪些资源需要白名单？
  • 如何避免资源混淆后的 Resources.NotFoundException？
  • 如何把 AabResGuard plugin JAR 放到 Gradle 项目里？

核心结论

资源混淆适合在 release 包里降低资源可读性，但必须先梳理 SDK、动态资源和反射访问路径。

白名单策略

应用图标、启动页、Firebase、广告 SDK、推送、WebView、动态加载资源和外部配置引用的资源都应谨慎保留。

Gradle 配置

项目应把 AabResGuard 插件 JAR 放到固定目录，并在 build.gradle.kts 中引用明确版本，方便升级和回退。

ADB Pro 怎么帮忙

Res Guard 可以管理插件 JAR、生成配置和白名单，Release Readiness 帮你在发版前检查相关风险。
