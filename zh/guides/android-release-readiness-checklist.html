发版检查

Android APK 与 AAB 发版前检查清单

覆盖 debuggable、API Key、minification、resource shrinking、签名、依赖、SDK、16 KB page-size 和 CI/CD 准备。

约 9 分钟

快速结论：一个 release-ready Android 构建应该通过安全、签名、压缩、SDK 合规、native 兼容性和依赖健康等检查。

开发者常问的问题

  • Android App 发布前应该检查什么？
  • 如何发现 debug flag 和暴露的 API Key？
  • 哪些 Gradle 和签名设置影响发版？
  • 如何检查 native libraries 的 16 KB page-size 兼容性？

核心结论

发版检查的目标是把不会编译失败、但会上线出事故的问题提前暴露出来。

检查范围

建议覆盖构建类型、debuggable、cleartext traffic、R8、资源压缩、签名、versionCode、targetSdk、API Key、测试域名和 native 兼容性。

版本号判断

versionCode 与本地历史相同只能作为提醒，真正是否会被商店拒绝，取决于目标商店已经接受过的版本基线。
