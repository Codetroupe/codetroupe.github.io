AAB 工作流

AAB 转 APKS 安装指南：bundletool、签名与设备部署

讲解如何把 Android App Bundle 转成 APKS、签名、安装到单台或多台设备，并避免常见 bundletool 和设备选择错误。

约 8 分钟

快速结论：本地安装 AAB 需要 bundletool、生成 APKS、正确签名，以及明确是面向单个目标设备还是多设备 Universal APK 测试。

开发者常问的问题

  • 如何把 AAB 安装到设备？
  • bundletool 如何把 AAB 转成 APKS？
  • 为什么 bundletool install-apks 会失败？
  • 多设备测试应该用 Universal APK 还是 split APKs？

为什么 AAB 安装不同

AAB 是发布输入，不是安装输出。bundletool 会根据设备配置生成一组 APK，这些 APK 才能被安装到 Android 设备。

手动流程

准备 bundletool、选择 AAB、提供签名配置、选择 connected device，运行 build-apks，然后 install-apks。多个设备连接时必须明确 device-id 或使用适合批量安装的 Universal APK。

常见错误

常见错误包括直接 adb install .aab、设备配置和 APKS 不匹配、只选了一个 ABI、多个设备连接却没有指定 device-id、签名不一致导致升级失败。

ADB Pro 如何帮助

AAB Tools 将 AAB 扫描、bundletool 管理、签名配置、设备选择和安装结果放进同一个 JetBrains IDE 面板。单设备可做 split APKS，多设备自动提示 Universal APK。

FAQ：Android Studio 能直接安装 AAB 吗？

它能部署当前工程变体，但独立 AAB 文件仍需要 bundletool 转换成 APKS/APK。

FAQ：APKS 文件里有什么？

APKS 包含一个或多个可安装 APK，以及设备配置和安装 metadata。

FAQ：本地 AAB 测试需要 release keystore 吗？

如果目标是验证上线候选包或升级路径，应该使用 release/upload 签名；临时功能测试可以用测试签名。
