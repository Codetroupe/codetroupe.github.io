Development behavior through version 0.1.8 · Reviewed November 5, 2026

1. Local code generation

The current development build analyzes Android projects and generates code locally. It has no publisher-operated advertising, analytics, crash-upload or project-upload service. Google account sign-in, OAuth tokens and service-account credentials are not required for local Google API template generation.

To identify modules and prepare changes, the plugin can read:

  • Gradle settings and module build files, including namespaces, application IDs and dependency configuration.
  • Android Manifest content and source paths, including Kotlin text used to detect Compose.
  • Existing contents of files targeted by a change plan, for previews and on-disk conflict checks.
  • Names and options you enter, including package, class name, language and update mode.

This project information is not uploaded to the publisher or Google as part of generation. Basic project checks look for selected local files; they do not verify every variant or upload Firebase configuration.

2. Files, temporary state and external actions

Previewing code does not apply a change plan. Selecting Apply Changes writes the reviewed source, guide and supported Gradle changes to your project. Those files remain after the plugin is disabled or uninstalled.

The current rollback mechanism keeps previous file bytes in memory for the session. It is not a persistent backup or native IDE Undo history, and it does not protect later edits when restoring or deleting files. Apply checks disk content rather than unsaved editor documents. Save and back up work before applying, and do not use rollback after editing affected files.

Copy puts the displayed content on the system clipboard. Your operating system and any clipboard-history or synchronization service govern it afterward. Official docs opens an external page in your browser; that site may process normal connection information under its own policy. The plugin does not attach project files or credentials to these documentation links.

IDE logging, local history, caches, backups, Marketplace installation and Gradle dependency downloads are separate IDE, operating-system or build-tool activities.

3. This documentation website

This website's source does not include advertising scripts, analytics scripts, third-party font requests, purchase forms or account sign-in. It stores the theme choice under googleplayapi-theme in your browser's local storage. You can remove that preference through your browser's site-data controls.

Example-code copy buttons use the clipboard only when you select them. Reading a guide does not provide a plugin trial or start an activation process.

The planned host is GitHub Pages. GitHub records visitor IP addresses for security purposes independently of this site's scripts. See the GitHub Pages data-collection explanation and GitHub Privacy Statement. External links open services with their own data practices.

4. Planned commercial licensing

The planned plugin is paid and closed source, with no trial. Commercial activation is not implemented in the current development package. Marketplace-managed purchases and license verification can involve a JetBrains account and licensing services under JetBrains' terms and privacy practices.

The final commercial version must document its actual activation flow, data fields, caching and offline behavior before release. A local-generation audit does not mean that future licensing will never use account information or a network connection. The website itself does not process payments or receive your license key.

5. Code running in your Android app

The plugin and the Android app you build are different software. Generated code calls Google SDKs after you integrate and build it into your application. Those SDKs' processing is governed by the chosen services, app configuration and your application's disclosures.

  • Play Integrity: send the returned token to your backend for verification. Keep server credentials outside the app.
  • Play Billing: verify purchase tokens and entitlements through a trusted workflow. This is your app's billing integration, separate from the IDE plugin purchase.
  • Firebase Analytics and Crashlytics: decide which events and diagnostics are collected, configure defaults and consent, and provide the app's own privacy information.
  • Updates and review: follow the relevant Play SDK requirements and data-safety guidance. A review callback does not confirm that a rating was submitted.

Firebase may initialize before Application.onCreate. When collection must stay disabled until a choice is resolved, configure defaults before that initialization and then apply stored choices. Adding a generated component alone is not a complete consent system.

References: Firebase privacy, Analytics collection controls, and Crashlytics collection controls.

6. Support and updates to this statement

The plugin has no built-in support-ticket upload. If you contact the publisher or use a linked support service, you choose what to send. Error messages and IDE logs may contain file paths. Remove secrets, personal data and confidential project content before sharing them.

The verified contact will be supplied on the Marketplace listing at release. Review this statement when accounts, licensing, telemetry, website forms or storage behavior changes. See the support guide for information to include in a report.
